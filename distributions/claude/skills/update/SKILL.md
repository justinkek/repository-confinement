# Updating repository-confinement

Running this skill is the go-ahead. Update, then say which version was
installed and which one is now.

The commands are below.

Stop and ask before anything they do not carry, and before a command that
removes an install rather than moving it forward.

## Afterwards

A session already running holds the old copy. The steps below say how to load
the new one, and what a hook prints comes from the copy that is loaded, so run
the reload skill after that and not before.

If it was already the latest, say so and change nothing.

## The steps for this install

One install serves several clients. Read the signatures, then follow the
steps under the one that matches.

### Claude Code, on your machine

A plugin directory under `~/.claude/plugins`, and a project directory you can
write to. Everything works, and settings persist.

    claude plugin marketplace update repository-confinement
    claude plugin update repository-confinement@repository-confinement

Load the new copy into a session already running by restarting it or running
`/reload-plugins`.

If the version does not move, the marketplace snapshot is stale: the first of
the two commands failed or was skipped.

Your settings are in `~/.repository-confinement` and no install touches them.

### ZCode

A plugin cached under `~/.zcode`, and no `~/.claude/plugins`. Everything works
as it does on Claude Code, and settings persist, but the window that installed
it is ZCode's own.

Update it under Settings, Plugin Management, where it was added. The bundled
command line cannot install or update a plugin, so the only way in is the
window.

Your settings are in `~/.repository-confinement` and no update touches them.

### Claude Cowork

A plugin directory under `~/.claude/plugins`, with `~/.repository-confinement/state`
written this session. Every hook runs, and the container is discarded when the
session ends.

Open the plus menu, then Plugins, then Manage plugins, and update it there.
